# 性能审查与优化计划

日期：2026-10-16。状态：优化实现、批量验证和性能探针已完成。

本计划针对目录浏览、图片、传输及 mpv 播放路径。以下代码行为已经核实，但耗时、内存和耗电收益尚未实测；优先级表示建议执行顺序。先建立基线，再实施优化，全部修改完成后集中验证。

## 目标与边界

- 大目录搜索、多选和滚动保持响应，减少主线程计算及短期对象分配。
- 降低重复目录请求、重复解码和传输临时文件读写，保持缓存额度可控。
- 减少后台及隐藏媒体控件时的无效轮询和界面更新。
- 保留路径边界、版本检查、目标回读校验、删除前复核、原子发布、取消清理和操作日志；不通过减少安全检查换取速度。
- 不改变四标签、共享 WebDAV 连接、跨存储剪贴板及按字节显示进度的交互。
- 不预设持久化视频分段缓存、全局并发传输或播放器更换；这些变更须有性能数据支持。

## 实施步骤

### P01：目录派生状态与排序

1. 以目录结果版本、查询和排序方式为输入缓存可见列表；页面只读取一次并传给列表、空状态和滚动恢复。
2. 对文件名小写值及修改时间戳每项只计算一次。明确大小未知、无效日期和目录优先规则，保持当前排序结果。
3. 大目录筛选排序使用 Default 调度器和可取消任务；查询变化使用最新请求胜出策略，旧目录及旧标签结果不得回写。
4. 检查 `DirectFiles.list`、SAF list、`parseListing` 与 UI 的双重排序；仅在调用方契约确认后移除重复步骤。

验收：同一输入下普通重组不再次排序；1 万项目录多选、显示传输进度不触发全量排序；快速输入、切换标签后结果身份正确。

### P02：状态写入合并

1. 保留 SavedStateHandle 的即时更新，对搜索等普通磁盘保存使用可合并的最新快照及短延迟写入。
2. `persistBrowserNow` 保持严格的完成屏障：等待其对应状态或包含该状态的更新版本真正落盘，成功前不得删除传输日志。
3. 状态 JSON 编解码移出主线程；有界队列或版本化状态不能丢弃屏障的完成通知，也不能让旧快照在新状态后写入。
4. 检查退出、进入后台及 ViewModel 销毁的收尾策略；保留失败可见性和进程重建语义。

验收：连续输入 30 次时写入量显著下降，队列保持有界；逐项移动后的剪贴板和日志恢复测试继续通过。

### P03：批量删除元数据请求

1. 用 `LocalStorage.stat` / WebDAV Depth=0 stat 获取目标身份，保留当前版本比较及条件 DELETE。
2. 图片删除及跨存储顶层源校验也存在父目录扫描，单独检查是否可使用相同策略。
3. 服务器对文件 stat 不兼容时，保留受控回退；不得以缓存元数据代替删除前的实时校验。

验收：删除 K 个文件不再为每个文件下载包含 N 项的完整目录；记录请求数量和响应字节数，同时覆盖文件替换、207 部分失败和取消。

### P04：进度发布与批量结果

1. 单个任务使用一个进度收集器，后台只更新最新值；建议 UI 每 100–200 ms 最多更新一次。
2. 阶段变化、完成及错误立即发布；保留真实字节数、未知总量和服务端 COPY/MOVE 的不确定进度。
3. 进度带任务及文件身份，任务取消或切换后旧回调不得更新下一任务。
4. 配合 P10 增量维护已完成集合，减少列表复制；剩余剪贴板的持久化仍须逐项可靠完成。

验收：快速传输时主线程协程投递次数有明确上界；最后一次字节数不丢失，取消和立即开始新任务不串进度。

### P05：图片缓存与解码

1. 查询统一的缩略图内存缓存后再访问磁盘；磁盘命中也写回内存，并与冷加载共用有界解码资源。
2. 保留相同 key 的请求合并，评估条带锁对不同图片的无关阻塞；只有测到争用后才改为按 key 管理。
3. 核实 Coil 对冷缩略图请求的原始响应缓存行为。明确 `thumbnails` 与 `original_images` 的职责，避免浏览缩略图列表导致原图缓存大量周转。
4. 评估仅预取相邻一张图片，取消不再需要的请求；设定并发、内存及流量预算后再启用。

验收：热缩略图命中不再重复磁盘解码；快速往返滚动的解码数、GC 和峰值内存下降；删除后两级缓存失效、版本变化和 GIF 行为保持正确。

### P06：传输读写放大

1. `copyBounded` 可返回字节数及增量 SHA-256；源写 staging 时同步计算摘要，避免随后完整读 staging 一次。
2. 目标回读直接计算摘要，省去 `verify` 文件；删除前源复核也可流式计算，但不得删除最终安全分离后的摘要验证。
3. 保留每阶段大小、版本及空间检查。空间检查可按已确认余量和写入预算触发；遇到 ENOSPC 仍要清理和报告，不得只在开始时检查。
4. 小文件场景记录日志写入次数及耗时，区分安全变更前记录和非关键阶段描述；未证明崩溃恢复等价前不合并强制落盘。

验收：相同文件摘要与故障处理不变，减少完整临时文件读写次数及峰值工作空间；513 MiB 及更大文件、低空间、源替换、丢响应和取消场景通过。

### P07：播放器采样与资源使用

1. 利用 mpv 属性观察更新暂停、缓存、时长和轨道状态；回调数据在 native 回调内提取，主线程发布。
2. 只在前台按需采样进度。控件隐藏时降低 UI 更新频率，暂停或后台时停止无效轮询；进入后台、旋转和退出仍立即保存位置。
3. 轨道列表在打开菜单或轨道变化时刷新，避免随进度重组反复解析 MPVNode。
4. 测量 MPV 初始化、Surface 绑定及 close 的主线程阻塞；在确认 AAR 线程契约前不把 native 生命周期操作直接移到 IO。
5. 测量高码率视频的代理吞吐和 mpv 预读内存，再决定缓冲参数；保留现有代理连接及队列上限。

验收：后台停止周期性 UI 采样；隐藏控件时 JNI 调用数下降；首帧、拖动恢复和 CPU 数据无回退，既有 Surface、倍速、音轨、字幕及息屏回归通过。

### P08 / P09：大目录解析与 SAF

1. 优先为 PROPFIND 列表逐条构造 FileEntry，释放已解析节点；保留响应体字节上限、深度限制、实体限制、propstat、去重及路径边界校验。
2. DELETE/COPY/MOVE 的 207 验证保持完整语义，可暂时保留现有解析器。
3. SAF query 使用可取消的 CancellationSignal；BFS 验证循环增加取消检查，保留遍历数限制。
4. 只在单次只读遍历或受控操作上下文中复用成员关系；重命名、移动、权限变化及 provider 变化后失效。禁止使用 document ID 字符串前缀猜测归属。

验收：接近 8 MiB 的目录响应峰值内存下降，取消请求及时释放；不支持 isChildDocument 的 provider 测试覆盖访问计数、取消、边界和文档移动。

## 实施记录

- P01：新增 `VisibleFilesState`。小目录使用派生状态缓存；超过 1,000 项在 Default 调度器筛选排序，取消旧计算并按完整输入校验结果。排序键每项预计算一次，页面复用同一可见列表。
- P02：新增 `CoalescingStateWriter`。普通状态用单槽信号和最新快照合并，强制保存保留独立版本完成通知；JSON 编解码在 IO 执行，Activity 进入后台时请求落盘。ViewModel 销毁仍以系统保存状态及最近落盘快照恢复，不承诺进程被强杀时执行异步收尾。
- P03：文件删除及图片删除使用实时 stat。WebDAV 仅对明确不支持 Depth=0 的 400/405/501 响应回退到父目录查询；权限、认证及其他错误不会触发扩大请求。跨存储的远端源及直接本地源同样按项检查；SAF 顶层源保留父目录成员校验。
- P04：新增 `TransferProgressPublisher`，每个文件只有一个收集器；同阶段每 150 ms 最多发布一次，新阶段及结束发布最新值，结束后拒绝旧回调。
- P05：缩略图先查内存，磁盘命中写回内存；磁盘及网络解码共用三并发限制。缩略图冷请求禁用 Coil 原图磁盘缓存，独立缩略图文件仍保留。未改变条带锁，未启用相邻原图预取，避免在缺少内存及流量实测时扩大占用。
- P06：源 staging 写入同时算摘要，目标回读及删除前源复核直接流式算摘要；不再创建 verify/source-verify 副本，单文件只需一份 staging。保留目标完整回读、版本比较及分离后删除摘要检查。可用空间按最多 4 MiB 预算刷新，临近预留空间时提前检查；保留 32 MiB 余量及实际写入失败处理。
- P07：mpv 属性观察驱动暂停、时长、速度和缓存状态；只在前台加载完成后采样位置，显示控件时 300 ms，隐藏时 1 秒，暂停后只采样一次，后台不采样。轨道仅在菜单打开或轨道变化时读取；native 生命周期及代理上限保持原约束。
- P08：PROPFIND 使用有字节上限的流和逐 response 解析，仅保留当前 response 子树；保留深度、实体、路径、propstat 与去重规则，其他 207 验证仍使用原解析器。
- P09：SAF 查询绑定 CancellationSignal，遍历和游标循环检查取消。没有引入跨调用成员关系缓存，避免 provider 外部移动后使用过期归属；保留每次操作的边界校验。
- P10：批量结果改为可观察增量列表，剩余剪贴板使用有序映射；传输计划只展开一次。日志目录创建移到 IO，仍保留变更前日志和逐项完成后的剪贴板持久化。

新增验证：状态合并及保存失败恢复、进度限频和过期回调、流式摘要和空间预算、排序等价和取消、1 万项查询/标签切换、Depth=0 回退边界、分块 XML/路径/实体/字节上限、流式下载取消、SAF 回退遍历取消。另提供显式开启的旧/新日期排序对照采样和 2 GiB 真实本地复制探针，普通功能测试不使用耗时阈值。

## 实际验证结果

- 构建：`assembleDebug`、`assembleDebugAndroidTest`、`testDebugUnitTest` 成功；48 项 JVM 单元测试通过。
- 设备：API 36 x86_64 模拟器完整回归 41 项通过，覆盖 WebDAV、SAF、跨存储、媒体和恢复流程。
- 日期排序探针（20 次交替采样）：1,000 项旧实现中位数 434.8 ms / 新实现 17.0 ms；10,000 项旧实现 6,138.4 ms / 新实现 169.8 ms。对应 P95 分别为 466.6/22.4 ms 和 8,318.6/218.1 ms。
- 2 GiB 本地复制探针：29,834.9 ms，最大同时 staging 文件数 1，摘要校验和清理通过。
- 空间预算单元测试显示 144 次 64 KiB 检查降为 3 次预算刷新；这是算法计数，不是设备吞吐结论。
- 限制：只有 x86_64 模拟器，未测 ARM64 真机、500 张图片和高码率硬解；上述性能数据不能外推到这些设备。测试结束后保留模拟器和应用运行。
